# 揭棋连线自动走棋（Line Connect）

在原「图片识别」能力之上，为 JieqiBox 增加了在别的对弈平台（天天象棋等）上自动落子的功能。

> 本分支包名为 `com.jieqibox.lineconnect`，与官方 JieqiBox（`com.jieqibox.app`）不同，
> 可以同时安装、配置互不干扰。

## 原理

```
对弈 App 画面 ──(MediaProjection 截屏)──▶ 前台服务缓存最新帧
        │
        ▼  base64 JPEG（只传棋盘区域）
   Vue 前端连线面板 ──(best.onnx / onnxruntime-web)──▶ 识别棋盘与棋子
        │
        ▼  10×9 检测结果 → 揭棋 FEN（含暗子池）
   UCI 引擎（Pikafish 揭棋版）分析
        │
        ▼  bestmove (如 h2e2)
   屏幕坐标换算 ──(无障碍 dispatchGesture)──▶ 对弈 App 自动落子
```

## 使用流程

1. **装引擎**（只需一次）
   - 从 <https://github.com/official-pikafish/Pikafish/tree/jieqi> 获取 Android 版引擎文件，
     在「引擎管理」里选中；App 会复制到私有目录并赋予执行权限。
2. **开权限**（只需一次）
   - 工具栏点粉色接入点图标打开连线面板。
   - 「申请截屏权限」→ 系统弹窗确认。
   - 「打开无障碍设置」→ 启用「JieqiBox 自动走棋」，可用「测试点击」验证。
   - 首次用悬浮窗还需授予**「显示在其他应用上层」**。
3. **连线**
   - 切到对弈 App 进入一局，再切回来点「开始连线」，然后切回对弈 App 即可。

## 我方走棋方：自动判断（默认）

每局你可能是红方也可能是黑方，不需要手动改。判断依据：

1. **开局局面**：揭棋开局布局是固定的，识别到它就按规则确定「红方先行」。
2. **对手走子**：棋盘变化了但我们没有落子 → 刚才走子的必然是对手，
   由此直接确定我方颜色。
3. **等待兜底**：启动后一段时间内棋盘没有变化 → 说明轮到我方，按当前走子方判定。

状态行会显示「我执黑」，日志里有「自动判断」记录。面板里仍可手动指定红/黑。

## 悬浮窗

启动截屏后自动显示一条可拖动的控制条：

```
[新局][连线][自动][变招][棋盘]                      [✕]
我执黑 · 黑方走 · 识别中     评估 +0.35     等待 3秒
```

| 按钮 | 作用 |
| --- | --- |
| 新局 | 重置识别状态（暗子池、走子方、判断结果），开新对局后按一下 |
| 连线 / 断开 | 开始和停止整个识别循环（运行时变红显示「断开」） |
| 自动 / 分析 | 显示当前模式，点击切换：**自动**会真的落子，**分析**只识别分析 |
| 变招 | 让引擎换一步：重新分析并排除刚走过的着法 |
| 棋盘 | 显示/隐藏棋盘窗口（见下） |
| ✕ | 停止连线并关闭悬浮窗 |

- **拖动**状态条移动整个悬浮窗；**点一下**状态条折叠/展开按钮行。
- 第二行显示：我方执子、当前走子方与阶段、引擎评估、等待秒数。

## 棋盘窗口与箭头

按「棋盘」弹出一个独立窗口，实时显示识别到的局面：

- **拖动棋盘**移动窗口；**拖右下角手柄**调整大小（保持 9:10 比例）；**右上角 ✕** 关闭。
- 棋盘上会画两种箭头：
  - **蓝色粗箭头** —— 引擎建议的着法；
  - **琥珀色细箭头** —— 上一手棋。

用途有两个：一是随时核对识别对不对（少子、暗子数量不对就说明这一帧识别有问题），
二是分析模式下可以直接看引擎推荐。

## 速度与稳定性

识别管线做了这几件事，前两件是主要收益。

### 1. 用可变输入尺寸的模型（最大的一环）

上游 `best.onnx` 的输入形状是**写死的 `[1,3,640,640]`**，无论棋盘多大，每次推理都按
640² 计算。仓库里的 `export-model.yml` 用 `dynamic=True` 重新导出同一份权重并发布到
`line-connect-model` release，应用即可按 **416** 运行 —— 计算量约为原来的 0.42 倍。

应用启动连线时会读取模型的实际输入形状：

- 模型支持可变尺寸 → 使用面板里的「模型输入边长」（默认 416）
- 模型是固定尺寸 → 自动使用它自己的尺寸，不会出错

> 想让提速生效，必须跑一次 `export-model.yml`，再跑一次 APK 构建（构建会优先使用
> 该 release 里的模型，其次仓库内 `models/best.onnx`，最后才回退上游权重）。

### 2. 每走一步只推理一次

- 只截取**棋盘区域**送入模型：传过 JS 桥的数据量降到约 1/10，
  棋子相对模型输入的尺寸也大得多，小棋子和暗子更容易认对。
- 原生每帧算一个 16×16 亮度指纹得出「画面变化比例」，**只看棋盘区域**
  （状态栏时钟不会干扰）。画面没变化时不跑推理，直接把上一次的识别结果
  当作对同一局面的又一次观测 —— 这既省算力，又让稳定判定能正常推进。
- 于是对手思考的整段时间是零开销，轮到我们时只花一次推理。

### 3. 引擎侧

- 分析前先 `stopAnalysis` 并等引擎空闲：否则引擎还在思考时新的分析会被忽略，
  白白等到超时 —— 这是之前「走不出来」的主要原因之一。
- 去掉了「走子方不符就翻转重试」的循环，它每次会多花一整个分析周期。

### 4. 其他

- 整屏传输最长边限制 1280。
- 裁剪识别若发现棋子数异常，会作废缓存并重新全图定位。
- 棋子数少于 6 时不落子。

诊断面板会显示：本轮模式（全图定位 / 棋盘裁剪 / 沿用上一帧）、画面变化比例、
推理耗时、原生心跳、识别到的我方执子与当前评估。

## 参数

| 参数 | 说明 |
| --- | --- |
| 我方执子 | 自动判断 / 红 / 黑 |
| 判断等待时间 | 自动判断时，等对手先走多久；超过则视为轮到我方 |
| 落子方式 | 两次点击 / 拖拽 |
| 识别间隔 | 每轮截屏间隔（默认 400ms） |
| 思考时间 | 每步引擎 movetime（默认 800ms） |
| 截屏缩放 | 截屏分辨率比例 |
| 稳定帧数 | 连续多少次相同观测才行动（默认 2） |
| 点击间隔 | 两次点击之间的等待 |
| 模型输入边长 | 模型支持可变尺寸时生效（默认 416） |
| 裁剪输入边长 | 裁剪后传给模型的最长边 |
| 重新定位间隔 | 每多少次裁剪识别做一次全图定位 |
| 变化判定阈值 | 画面变化超过多少才重新识别 |
| 自动走棋 | 关闭则只分析、不落子 |

## 手工标注样本（可选）

如果固定某个平台长期使用、且识别确实不稳，用你自己的截图微调会明显改善。

1. **采集**：面板点「开始采集」。整屏截图 + 当前模型识别出的框会一起存到
   `Pictures/JieqiBoxLine/`（`sample_*.jpg` + `sample_*.json`），自动跳过重复帧。
2. **标注**：打开 `tools/labeler/index.html`（单文件离线页面），
   一次选中该目录下的 jpg 与 json —— json 里的框会自动填好，
   只需要拖一拖、删掉错的、补上漏的，再导出 `annotations.json`。
3. **训练**：`tools/dataset/build_dataset.py` 转成 YOLO 数据集，
   `train-line-connect.yml` 在 CI 上微调并发布新模型。

## 安全与边界

- 截屏权限由系统弹窗授予，随时可在系统设置撤销，且只用于识别棋盘。
- 无障碍服务只用于发送点击/滑动手势，不读取、不上传界面内容。
- 识别与引擎均在设备本地运行。
- 请遵守对弈平台的使用条款，本功能仅用于本地研究/辅助。

## 依赖的原生组件（仅 Android）

| 文件 | 作用 |

| `LineConnectOverlay.kt` | 可拖动悬浮控制条 |

| `LineConnectBridge.kt` | `window.LineConnect` JS 接口 |
| `MainActivity.kt` | 注册桥接、截屏授权回调、后台事件派发 |
