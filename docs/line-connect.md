# 揭棋连线自动走棋（Line Connect）

在原「图片识别」能力之上，为 JieqiBox 增加了在别的对弈平台（天天象棋等）上自动落子的功能。

> 本分支包名为 `com.jieqibox.lineconnect`，与官方 JieqiBox（`com.jieqibox.app`）不同，
> 可以同时安装、配置互不干扰。

## 原理

```
对弈 App 画面 ──(MediaProjection 截屏)──▶ 前台服务缓存最新帧
        │
        ▼  base64 JPEG
   Vue 前端连线面板 ──(best.onnx / onnxruntime-web)──▶ 识别棋盘与棋子
        │
        ▼  10×9 检测结果 → 揭棋 FEN（含暗子池）
   UCI 引擎（Pikafish 揭棋版）分析
        │
        ▼  bestmove (如 h2e2)
   屏幕坐标换算 ──(无障碍 dispatchGesture)──▶ 对弈 App 自动落子
```

与原有「图片识别」的区别：图片识别是**手动选一张图**导入局面，连线是**持续截屏 + 自动分析和落子**。

## 使用流程

1. **装引擎**（只需一次）
   - 在电脑上下载 Pikafish 揭棋分支的 Android 可执行文件：
     <https://github.com/official-pikafish/Pikafish/tree/jieqi>
   - 在 JieqiBox 工具栏打开「引擎管理」，选择该文件；App 会把它复制到私有目录并赋予执行权限。
2. **开权限**（只需一次）
   - 工具栏点击「连线自动走棋」图标（粉色接入点图标）。
   - 点「申请截屏权限」，系统弹窗中选择要共享的屏幕/应用。
   - 点「打开无障碍设置」，启用「JieqiBox 自动走棋」。可用「测试点击」验证是否生效。
3. **连线**
   - 切到对弈 App，进入一局揭棋，轮到你走时切回 JieqiBox，点「开始连线」。
   - App 会每 ~0.9 秒截一次屏，识别到局面稳定后交给引擎，然后把着法点击/拖拽到对弈 App 上。
   - 之后再切回对弈 App 即可，前台服务会让截屏和轮询继续运行。

> **建议先开「演练模式」**：只识别、只分析、只打日志，不真的点击。确认识别稳定后再关闭。

## 悬浮窗（切到对弈 App 后仍可操作）

启动截屏后，应用会自动显示一个可拖动的悬浮控制条：

```
[新局][扫描][自动][变招][棋盘][本应用]            [✕]
轮到红方 · 识别中        评估 +0.35        等待 3秒
```

| 按钮 | 作用 |
| --- | --- |
| 新局 | 重置识别状态（暗子池、走子方），在自己点开新对局后按一下 |
| 扫描 | 立即执行一次识别（不落子），用来确认棋盘识别正常 |
| 自动 | 开始 / 停止自动走棋（运行中变红显示「停止」） |
| 变招 | 让引擎换一步：重新分析当前局面并排除刚走过的着法 |
| 棋盘 | 显示 / 隐藏**棋盘悬浮窗**（见下） |
| 本应用 | 把 JieqiBox 切回前台 |
| ✕ | 停止连线并关闭悬浮窗 |

交互：

- **拖动**状态条（第二行）可移动整个悬浮窗，位置不会自动重置。
- **点一下**状态条可折叠 / 展开按钮行，减少遮挡。
- 第二行实时显示：轮到哪方、当前阶段、引擎评估、等待秒数。

首次使用需要授予 **「显示在其他应用上层」** 权限（面板里点「授予权限」会跳到系统设置）。

## 棋盘悬浮窗

按「棋盘」会弹出一个独立的棋盘窗口，实时显示**当前识别到的局面**：

- **拖动棋盘任意位置** → 移动窗口
- **拖右下角手柄** → 调整大小（保持 9:10 棋盘比例）
- **点右上角 ✕** → 关闭

用途是随时核对识别对不对：如果棋盘上少了子、多了子，或暗子数量不对，
说明这一帧识别有问题，可以据此调整「截屏缩放」「识别间隔」等参数。

### 一个必要的实现细节

WebView 在不可见时会被系统节流甚至暂停 `setTimeout`，如果识别循环只依赖 JS 定时器，
一切换到对弈 App 就会停摆。

因此轮询循环改由**原生侧驱动**：`ScreenCaptureService` 按设定间隔调用
`window.__lineConnectTick__()`。`evaluateJavascript` 在后台仍然有效，而 ONNX 推理是
Promise 微任务、不受定时器节流影响，所以切到别的应用后走棋会继续进行。

打开「诊断信息」可以看到 **原生心跳** 计数，它会持续增长说明后台循环正常。

## 速度与稳定性

识别管线做了三件事，前两件是速度和准确率的主要来源。

### 1. 只识别棋盘区域（默认开启）

首次定位到棋盘后，后续每一轮都只截取棋盘那一小块送进模型：

- 传过 JS 桥的数据量降到约 1/10，省掉大量 base64 拷贝和解码
- 棋子相对模型输入的尺寸大得多（原先整屏缩放后棋子只占二三十像素），
  小棋子、暗子、被挡住一半的棋子都更容易认对
- 不再依赖 `Board` 框做双线性插值，直接按裁剪区域线性映射到 9×10 格

每隔「重新定位间隔」轮做一次全图定位，防止裁剪框失效。

### 2. 画面没变就不识别（默认开启）

原生侧对每一帧算一个 16×16 的亮度指纹，和上一帧比较得到「变化比例」。
比例低于阈值时直接跳过这一轮 —— 对手思考、以及不在自己回合的绝大部分时间都是零开销。

副作用是识别间隔可以调小（默认已从 900ms 降到 500ms），
反应更快但平均 CPU 反而更低。

### 3. 更省的传输

整屏截图传给 webview 时最长边限制在 1280，避免超大屏手机每轮搬运几百 KB 的 base64 字符串。

诊断面板会显示**本轮模式**（全图定位 / 棋盘裁剪 / 跳过）、**画面变化**比例和**推理耗时**，
可以据此判断瓶颈在哪。

## 手工标注样本（可选，但对特定平台很有效）

模型 `best.onnx` 是在作者自己的数据集上训练的。不同对弈平台的棋子画法、配色、
大小都不一样，**拿你自己的截图微调一遍，识别率会有明显提升** ——
这就是「手工标一点图」的道理，方向是对的。

内置了一套采集 → 标注 → 训练的流程。

### 1. 采集

面板里点「开始采集」，然后正常连线即可。应用会把整屏截图和**当前模型识别出的框**
一起存下来：

```
Pictures/JieqiBoxLine/
  sample_1737000000000.jpg
  sample_1737000000000.json   ← 已带好模型预测的框
```

存储位置优先用 `Pictures/JieqiBoxLine`（文件管理器、相册都能看到），
没有存储权限时退回应用私有目录。采集会自动跳过画面没变化的帧，不会存重复图片。

### 2. 标注

打开 `tools/labeler/index.html`（纯本地单文件页面，无需联网）：

1. 点「选择图片」，一次选中该目录下的 `sample_*.jpg` 和 `sample_*.json`
2. json 里的框会自动填好（显示为虚线框），只需**拖一拖、删掉错的、补上漏的**
3. 点类别按钮切换当前类别，选中框后按 `1`–`9` 快速改类；按 `Delete` 删除
4. 点「导出」得到 `annotations.json`

页面适配了触摸，手机上也能用。**修正已有框比从零画框快得多**，这是关键。

### 3. 训练

- `tools/dataset/build_dataset.py`：把样本图片 + `annotations.json` 转成 YOLO 数据集
- `.github/workflows/train-line-connect.yml`：在 CI 上微调并产出新的 `best.onnx`

把新的 `best.onnx` 放回模型位置即可生效。

> 坦白说：如果只是偶尔换平台玩，先把「截屏缩放」和阈值调好往往就够了；
> 只有在固定某个平台长期使用、且识别确实不稳时，微调才值得投入。

## 参数

| 参数 | 说明 |
| --- | --- |
| 我方执子 | 红 / 黑，决定引擎分析的走子方 |
| 落子方式 | `两次点击`（点起点→点终点）或 `拖拽` |
| 识别间隔 | 每轮截屏的间隔，默认 900ms |
| 思考时间 | 每步交给引擎的 movetime |
| 截屏缩放 | 截屏分辨率比例；太低会导致棋子太小识别不到 |
| 稳定帧数 | 连续多少帧识别结果一致才认为局面稳定 |
| 点击间隔 | 两次点击之间的等待 |
| 演练模式 | 只分析不点击 |

## 安全与边界

- **截屏权限**由系统弹窗授予，随时可在系统设置中撤销。
- **无障碍服务**只用于发送点击/滑动手势，配置里 `canRetrieveWindowContent` 之外不读取界面内容，也不上传任何数据。
- 识别完全在设备本地用 ONNX 模型完成；引擎也在本地运行。
- 请遵守对弈平台的使用条款，本功能仅用于本地研究/辅助。

## 依赖的原生组件（仅 Android）

| 文件 | 作用 |
| --- | --- |
| `ScreenCaptureService.kt` | MediaProjection 前台服务，缓存最新帧为 JPEG |
| `AutoPlayAccessibilityService.kt` | 无障碍手势注入（tap / swipe） |
| `LineConnectBridge.kt` | `window.LineConnect` JS 接口 |
| `MainActivity.kt` | 注册桥接、处理截屏授权回调 |
